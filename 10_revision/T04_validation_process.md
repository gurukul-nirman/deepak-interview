# T04 · Validation process & findings — quick refresher
**Study:** `03_monitoring_validation/02_independent_validation_playbook.md` · **Test:** `START TOPIC T04`

## 60-second summary
- Core elements: **conceptual soundness · ongoing monitoring · outcomes analysis** (SR 11-7 and SR 26-2) + data, implementation, use.
- Scope by **tier** (inherent risk × materiality = exposure + purpose).
- Workstreams: purpose/use · data · conceptual soundness · replication · outcomes · benchmark/challenger · sensitivity · implementation · monitoring plan · use/overlays.
- Findings = **Condition · Criteria · Cause · Effect · Recommendation · Severity · Owner/date**. Outcomes: approve · approve with conditions · reject.
- Independence without hostility: firm on evidence, flexible on remediation path.

## Quick Q → short answer
| Q | A |
|---|---|
| Validation vs monitoring? | Independent 2nd-line assessment of the whole model vs 1st-line ongoing tracking |
| Validation types? | Initial, periodic (risk-based), change, annual/monitoring review, targeted, vendor |
| Replication? | Re-run/re-code development to reproduce results within tolerance |
| Benchmark vs challenger? | Any comparison point vs an alternative model; informs, doesn't replace |
| Implementation testing? | Prod vs dev parity, feeds, edge cases, parallel runs, controls |
| Severity levels? | High (restrict/fix fast), Medium, Low — bank-specific |
| Owner disputes a High finding before go-live? | Re-check evidence; keep severity if it stands; offer conditional approval (overlay, restricted use, monitoring, deadline); escalate via committee |
| Manager asks to downgrade? | Ask for new evidence; document; escalate — independence |
| Effective challenge (SR 26-2)? | Expertise + independence + organisational standing/influence |
| Vendor model? | Vendor docs for conceptual soundness; **local** outcomes & stability; segments; limitations; version control; customisations documented |
| Use before validation? | Allowed in urgent cases with limits, extra monitoring, stakeholder notice (SR 26-2) |
| Most-missed area? | Data, implementation and use — not statistics |
